# トピックス記事専用指示書（topics-article.md）

本書は、「みらいぎかいっち＠大分市」のトピックス記事（トピックスカード）を作成・更新する際の個別ルールおよびプロンプトの仕様を定めるものである。作業時は [全体共通ルール](20261021_1800_全体共通ルールmaster-workflow.md) を必ず遵守すること。

---

## 1. ページの基本仕様

### 【表側】サイト上の場所・役割
- **URLパス:** 記事カードは `/topics` に表示する。トップページには記事一覧への入口バナーを表示する。
- **役割:** 一つまたは複数の議案・会議を題材に、市民の暮らしに関わる話題を分かりやすく解説する読み物。議案そのものや会議全体の要約とは区別する。

### 【裏側】データベース構造
- **元データと表示:** 記事は `proposals` と `bill_articles` を参照する。現行の型定義では `bill_articles.bill_id` は `proposals.id` を参照する数値であり、議案の `bills.id` ではない。対象環境のスキーマと既存レコードを照合し、同名のIDを取り違えない。
- **表示値の優先:** 紐付く `proposals` に値がある場合、カテゴリ、審議状況、要約、詳細、理由、ポイント、対象者、賛成・慎重の声は、その値が `bill_articles` より優先される。片方だけを更新して表示が変わると決めつけず、両方と画面を確認する。
- **AIインタビューを付ける場合:** `bills` に **`source = 'topic'`** の行（インタビューの受け皿）を作り、その `bills.id` を `bill_articles.interview_bill_id` に設定する。受け皿は議案ではないため、議案一覧・議案詳細には表示されない（詳細は master-workflow.md「`bills` テーブルの住み分け」）。
- **公開状態:** Web側の `TOPIC_PUBLICATION_ENABLED=true` の場合のみ `publish_status='published'` を絞り込む。未設定・無効の場合、`draft` でも表示され得る。対象環境の設定とDBを確認し、共有DBに下書きを書けば安全だと考えない。DBの対応が済み管理画面側の同設定も有効な場合、トピックス管理で公開状態を操作できる。
- **審議状況との違い:** 記事に表示する「審議中」「予算可決」等は審議状況であり、記事の `draft` / `published` とは別である。

### 【リンク関係の仕組み】
- `bill_articles.source_refs` は会議ID・開催日ID・会議種別・会議名・日付・議案番号／名称・確認済み発言抜粋の配列。会議へのリンクはIDから組み立てられ、議案詳細へのリンクは公開済み議案と照合できた場合に表示される。IDや一致を推測せず、リンク先を確認する。

実装の確認先: [トピックスの取得処理](../web/src/features/bills/server/loaders/get-articles.ts)、[記事カードの表示](../web/src/features/bills/client/components/articles/article-accordion-card.tsx)。

## 2. ライティング・ガイドライン（トーン＆マナー）
- **文体:** 読者に語りかける、柔らかく誠実な丁寧語を使用する。
- **生活者目線:** 常に「この情報を知って、誰が・どう助かるのか？」という生活者目線を重視する。
- **賛成・慎重の声:** 出典に基づく意見と、想定した論点を区別する。実在する市民の発言であるかのような架空の引用は作らない。大分弁を使う場合も、実際の引用は原文を変えず、想定例はその旨を明示して掲載方法を確認する。裏付けのない声を無理に両方作らない。
- **タイトルの統一フォーマット:** `[ステータス] + 【議案・条例名】 + キャッチコピー` （※タイトルの文字数は全体で30文字以内を目安とする）。画面には別途ステータスバッジも表示されるため、重複して読みにくくないか確認する。
- **情報の密度と品質（情報の省略禁止）:**
  - 議会や行政が公開している詳細情報を「省略」してはならない。特に行政的な背景や経緯（詳細・理由）は、情報が持つ「深さ」を削らずに正確に言語化すること（「情報は濃く、表現はやわらかく」を徹底）。
- **中国語漢字の排除:** `议`、`务`、`该` 等の中国語漢字は一切使用しないこと。

## 3. データベース / 項目定義（入力フォーマット）
トピックス記事として登録・出力する際は、以下の項目構造を厳守すること：

1. **タイトル:** `[ステータス] + 【議案・条例名】 + キャッチコピー`
2. **ステータス:** 予算可決、法案成立、審議中、議会提言、提出前、計画承認 等
3. **カテゴリ:** 以下から記事の主なカテゴリを1つ選択する。表示には `proposals.badge` が優先される。
   - **子育て・教育**（子ども、学校、給食、教育、子育て支援など）
   - **安心・安全・防災**（災害対策、避難、防犯、地域の安全、鳥獣対策など）
   - **まちづくり・暮らし**（空き家、移住、交通、住環境、地域交流など）
   - **まちの仕組み・選挙**（選挙、投票率、若者応援、議会改革、条例など）
4. **要約（3行）:**
   - 1行目：概要1行目（何が決まったか）
   - 2行目：概要2行目（市民生活への影響・変化）
   - 3行目：概要3行目（今後のスケジュールや注意点）
5. **詳細:** 経緯や本質的な内容（300〜500文字。情報を削らず濃く記述）
6. **理由・背景:** 行政的な背景・意図（200文字以内）
7. **ポイント3つ:** 核心となる重要ポイントを3点漏らさず記述
`【ポイント】＋詳細`
8. **対象者:** 制度・決定の対象者（影響を受ける市民の層）
9. **賛成の声:** 確認できた期待・肯定意見、または想定例と明示した論点。
10. **慎重の声:** 確認できた懸念・慎重意見、または想定例と明示した論点。根拠のない実在の発言として扱わない。
11. **関連リンク:** 大分市役所など
12. **裏付けとなった会議・議録:** 会議名、議案番号、議案名、および議事録からの発言抜粋・詳細ページへのリンク情報

`source_refs` の各要素は `session_id`、`meeting_id`、`meeting_type`、`meeting_title`、`session_label`、`date`、`bill_number`、`bill_name`、`evidence_quote` を持つ。IDは実際の `meetings` / `meeting_sessions` と照合し、確認できない抜粋は作らない。

`decision_date` は議決日、`proposals.published_date` はサイト公開日であり、異なる日付である。新規公開・更新時は既存値と公開機能の設定を確認し、更新日を公開日として上書きしない。

## 4. AIへの依頼プロンプト（実務用テンプレート）
VSCodeなどでAIにトピックス記事の作成を指示する際は、以下のプロンプトをそのままコピーして使用してください。

```markdown
以下の【元となる議事録テキスト・関連議案のデータ】をもとに、「みらいぎかいっち＠大分市」のトピックス記事を作成してください。
DBには登録せず、見出しと本文の全文、出典、未確認事項を先に提示してください。
（※会議全体の要約ではなく、市民の暮らしに直結するテーマを深掘りする市民向け解説記事を作成すること）
中学生レベルの分かりやすさ、生活者目線、「情報は濃く、表現はやわらかく」を守ってください。声は出典のある意見と想定例を区別し、実在の発言を捏造しないでください。

【元となる議事録テキスト・関連議案のデータ】
（ここに、記事の根拠となる議事録の該当部分や発言内容、対象の議案情報を貼り付け）

【出力してほしいフォーマット】
以下の構成で出力してください：

## タイトル
（[ステータス] + 【議案・条例名】 + キャッチコピー。全体で30文字以内）

## カテゴリ
（子育て・教育 / 安心・安全・防災 / まちづくり・暮らし / まちの仕組み・選挙 から1つ選択）

## 要約（3行）
- 1行目：
- 2行目：
- 3行目：

## 詳細
（経緯や背景を含めた300〜500文字の解説文。情報を省略せず濃く、中学生にもわかる表現で）

## 理由・背景
（行政側の意図や背景。200文字以内）

## ポイント3つ
- ポイント1：
- ポイント2：
- ポイント3：

## 対象者
（この決定が直接影響する市民の層）

## 賛成・期待の声
（出典のある意見、または想定例と明示した論点。根拠がなければ無理に作らない）

## 慎重・懸念の声
（出典のある意見、または想定例と明示した論点。根拠がなければ無理に作らない）

## 裏付けとなった会議・議録（source_refs用）
- 会議ID・開催日ID・会議種別：（既存の `meetings` / `meeting_sessions` と照合）
- 会議名：（例：文教常任委員会（3月23日））
- 議案番号・名称：（例：議第35号 大分市学校給食の管理に関する条例の一部改正について）
- 議事録からの抜粋・発言内容：（実際の原文を確認し、未確認なら空欄）

【注意事項】
- 中国語の漢字（议、务、该 等）は一切使用しないこと
- 議事録の情報を省略せず、核心を正確に言語化すること
- 【トピックスと関連リンク】：
  `source_refs` のID・日付・議案情報を実データと照合し、表示できる会議リンクと議案詳細リンクを確認すること。本文の承認、本番DB書き込み、一般公開はそれぞれ確認すること。
```
