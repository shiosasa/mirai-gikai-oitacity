# 議事録要約ページ専用指示書（committee-summary.md）

本書は、「みらいぎかいっち＠大分市」の議事録要約ページを作成・更新する際の個別ルールおよびプロンプトの仕様を定めるものである。作業時は [全体共通ルール](20261021_1800_全体共通ルールmaster-workflow.md) を必ず遵守すること。

---

## 1. ページの基本仕様

### 【表側】サイト上の場所・役割
- **URLパス:** `/committees` は一覧への入口。開催日ごとの詳細は `/committees/plenary/{meeting_id}/{session_id}` または `/committees/committee/{meeting_id}/{session_id}`。
- **役割:** 開催日ごとに要約、決定事項、審議された議案、出席・欠席議員、および詳細議事録を、データがある項目について表示する。
- **議事録の未掲載:** 本会議一覧では、開催日が未登録、または全開催日の `content` が空の会期に「更新中」を表示する。開催日ごとにも原文が空なら「更新中」とし、要約や決定事項などが登録済みであれば引き続き表示する。詳細情報が何もない開催日は詳細リンクを表示しない。
- **要約の切り替え構造（詳細ボタン）:**
  - **やさしい要約:** デフォルトで表示される、中学生でも分かるように専門用語を排除して噛み砕いた概要。
  - **詳細な要約:** 「詳細ボタン（切り替えスイッチ）」を押すことで切り替えて表示される、議論の背景や行政的経緯など専門用語も交えて深く掘り下げた詳しい解説。
  - **ページ単位の設定:** 別ページを通常のリンクで開くと、やさしい要約から表示する。詳しい表示はそのページのURLの `?difficulty=hard` で指定し、サイト全体のCookie設定として引き継がない。同じURLの再読み込みやブラウザの戻る操作では、URLに指定された状態を維持する。
  - **未登録時の挙動:** やさしい要約があり、詳しい要約がない場合は、詳しい表示にしてもやさしい要約を残し、『詳しい要約は準備中です』を表示する。要約欄自体が空の場合は切り替え欄も表示されない。

### 【裏側】データベース構造
- **登録先テーブル:** 会議の基本情報は `meetings`、開催日ごとの `summary`、`detailed_summary`、`decisions`、`attendees`、`bills`、`content` は `meeting_sessions`。
- **公開時の注意:** `meeting_sessions` に下書き状態はない。共有DBを更新すると本番にも表示され得るため、内容の承認と本番DB書き込みの承認を別々に得る。

### 【リンク関係の仕組み】
- **出席議員・欠席議員のリンク:** 公開中の議員名と一致した場合に議員紹介ページへリンクする。一致しない場合は氏名のみ表示される。当局・行政側は議員欄に含めない。
- **審議された議案のリンク:** 会期・番号や名称で対応する公開済み議案を一意に特定できた場合に表示する。番号や名称を推測せず、実際のリンク先を確認する。
- **読み終えた後の移動:** 本会議・委員会の要約詳細ページの末尾に「一覧へ戻る」「ページ上部へ」を表示する。一覧はページ上部の戻り先と同じ。上部への移動は同じ文書内のアンカーを使い、詳しい表示を勝手に切り替えない。

実装の確認先: [会議の取得処理](../web/src/features/committee-minutes/server/repositories/meeting-repository.ts)、[出席者・議案の表示](../web/src/features/committee-minutes/server/components/session-extras.tsx)。

## 2. ライティング・ガイドライン（トーン＆マナー）
- **文体:** 読者に語りかける、柔らかく誠実な丁寧語を使用する。
- **情報の密度と品質（情報の省略禁止）:** 議会や行政が公開している詳細情報を勝手に「省略」せず、必要な文脈をしっかり残す。
- **改ざんの禁止:** 詳細議事録の作成にあたっては、元のテキストをベースに段落や見出しなどを綺麗に整えるのみとし、文章の意味の変更や改ざん（捏造・勝手な書き換え）は絶対にしないこと。
- **中国語漢字の排除:** `议`、`务`、`该` 等の中国語漢字は一切使用しないこと。

---

## 3. データベース / 項目定義（入力フォーマット）
議事録要約として案を作る際は、次の項目を会議・開催日ごとに整理する。`attendees` は `chair`、`vice_chair`、`members`、`absent`、`officials` を持つJSON、`bills` は `number`、`name`、`description`、`result` を持つ配列であり、現在の画面では `officials` を議員欄に表示しない。

1. **会議名:** （例：「経済環境常任委員会」「本会議」など）
2. **開催日:** DBでは `YYYY-MM-DD` 形式。画面では日本語の日付・曜日に整形される。
3. **やさしい要約:** デフォルト表示用。中学生でも一目で分かるよう、難しい言葉を噛み砕いた簡潔な概要
4. **詳細な要約:** 詳細ボタン切り替え用。深い解説データがある場合のみ入力（※未登録の場合は「詳しい要約は準備中です」の表示となる）
5. **決定事項:** 会議で決定した内容の箇条書き
6. **審議された議案（あれば）:** 議案番号・議案名・ステータス等（※議案詳細ページへのリンクに対応）
7. **出席議員・欠席議員:**
   - 議員のみを対象とし、委員長・副委員長・委員などの役職を明記する。
   - 議員紹介ページへのリンクおよびバッジ表示に対応させる。
   - （※当局・行政側のメンバーはここには含めない）
8. **詳細議事録:**
   - 議事録の元のテキストをベースにしつつ、市民が読みやすいように段落や見出しなどを綺麗に整理・整形したもの（※文章の改ざんは一切行わない）。
