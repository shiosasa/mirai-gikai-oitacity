# 議案詳細ページ専用指示書bill-detail.md

本書は、「みらいぎかいっち＠大分市」の議案詳細ページ・議案カード（`/committees/bill-pickups/[id]`）を作成・更新する際の個別ルールおよびプロンプトの仕様を定めるものである。作業時は [全体共通ルール](20261021_1800_全体共通ルールmaster-workflow.md) を必ず遵守すること。

## 1. ページの基本仕様
- **【表側】サイト上の場所・役割**
  - **URLパス:** /committees/bill-pickups/[id]
  - **役割:** 予算案や条例改正などの個別の議案について、市民がその内容、背景、重要ポイント、影響を受ける人を深く理解できるように解説するページ。
  - **審議のステータス（ステップバー）:** `bills.status` がある場合、議案上程・委員会審査・本会議採決・結果などの進捗を表示する。
  - **説明の詳しさ切り替え:** 「説明をもっと詳しく」で `bill_contents` の `normal` / `hard` を切り替える。`## 取り組みの詳細` の本文が切り替え対象で、`hard` がなければ「詳しい説明は準備中です」と表示する。その他の本文は `normal` を表示する。
  - **本会議での賛否:** 公式の議決結果PDFで議案番号・会期・正式名称・議員別の記号を照合し、既存の [BillVoteSection](../web/src/features/committee-minutes/shared/components/bill-vote-section.tsx) で人数・会派・議員名と出典ページを表示する。登録先は [bill-vote-snapshots.ts](../web/src/features/committee-minutes/shared/data/bill-vote-snapshots.ts)。議長は賛成人数に含めず、所管分だけを解説するカードでも賛否は議案全体へのものと明記する。「可決」「全員」などの結果だけから個々の議員の投票を推定しない。
- **【裏側】データベース構造**
  - **登録先テーブル:** 議案の基本情報・審議状態は `bills`、難易度別の説明文は `bill_contents`、出典となる開催日・議案リストは `meetings` / `meeting_sessions`。
  - **由来の区別:** 議案は必ず `bills.source = 'meeting'`（既定値）で登録する。`source = 'topic'` の行はトピックスのAIインタビュー受け皿であり、議案ではない（詳細は master-workflow.md「`bills` テーブルの住み分け」）。
  - **表示条件:** 議事録内の議案と公開済み `bills` を一意に対応付けられる必要がある。詳細本文には `normal` の `bill_contents.content` が必要。`hard` を登録する場合も同じ見出し `## 取り組みの詳細` を使う。
- **【リンク関係の仕組み】**
  - ページ内から、その議案を審議した「各会議（本会議・委員会）の議事録要約ページ」へ相互にリンクが張られる仕組み。
  - 対応する公開中のトピックス用AIインタビューを特定できた場合に導線を表示する。記事やインタビューのリンクが必ず付くと決めつけず、実画面で確認する。
  - カテゴリバッジは関連トピックスの `source_refs` による記事カテゴリと、議案に付いた `bills_tags` のタグ名から導出する。記事がなくても対応するタグで補える。既存の `tags.label` と議案IDを照合し、承認後に `bills_tags` へ紐付ける。
  - 賛否は[公式資料の記録](../web/src/features/committee-minutes/shared/data/bill-vote-snapshots.ts)に、採決時点の会派・議員ごとの結果を保存する。投票者の賛否が会派内で一致した場合のみ会派名にまとめ、分かれた場合と無所属は個人名を表示する。議長・欠席・退席・法律上の除外は賛否と分ける。会派名と現在の議員一覧に掲載されている会派名が一致すれば、その会派の位置にリンクする。同名の会派が現在の一覧にない場合は、その旨を表示し、議員一覧の先頭へリンクする。個人のリンク先は本人と一致する現在の議員紹介。
  - 賛否データは現時点では管理画面やDBから編集できず、新しい議案は公式資料・議案ID・会期・各議員の投票・会派・出典を照合して上記ファイルを更新する。`○` / `×` は賛成 / 反対、`欠` は欠席、`退` は退席、`除` は採決からの除外、`議` は議長の採決不参加を表す。確認内容をユーザーに提示し、公開前の承認を得る。

実装の確認先: [議案詳細の表示](../web/src/features/committee-minutes/server/components/bill-pickup-detail-view.tsx)、[議案ピックアップの組み立て](../web/src/features/committee-minutes/server/loaders/get-bill-pickups.ts)。

## 2. ライティング・ガイドライン（トーン＆マナー）
- **文体:** 読者に語りかける、柔らかく誠実な丁寧語を使用する。
- **生活者目線:** 単なる行政用語の解説にとどめず、「市民の暮らしにどう影響するのか」という視点を重視する。
- **情報の密度と品質（情報の省略禁止）:** 行政が公開している議案の主旨や理由、背景を勝手に削らず正確に言語化する（「情報は濃く、表現はやわらかく」）。
- **中国語漢字の排除:** 议、务、该 等の中国語漢字は一切使用しないこと。

## 3. データベース / 項目定義（入力フォーマット）
議案詳細の案は次の項目を議案ごとに整理する。背景・ポイント等は独立したDB列と決めつけず、実際の `bill_contents.content` のMarkdown構成と照合する。

1. **議案種別・番号:** （例：「予算」「法案」などのバッジ ＋ 「令和8年 議第75号」）
2. **議案名:** 正式な議案の名称。複数議案を扱うときは情報が混入しないよう議案ごとに分ける。同一の一般会計予算に複数のテーマがあるときは、議案IDを維持し、必要に応じてサブタイトルで区別する。
3. **審議のステータス:** 現在の進捗段階（議案上程、委員会審査、本会議採決、可決 / 否決 等）
4. **カテゴリタグ:** 子育て・教育、安心・安全・防災、まちづくり・暮らし、まちの仕組み・選挙 から選択（複数可）
5. **簡易概要:** 一目で内容がわかる短い説明文
6. **関連する議事録一覧:** 審議された本会議・委員会の日付と名称のリンク集
7. **取り組みの詳細:** 議案の具体的な内容や変更点の詳しい解説
8. **背景・理由:** なぜこの議案が必要になったのかの経緯・意図
9. **重要ポイント:** 核心となるポイントの箇条書き（3点など）
10. **主に影響を受ける人・対象者:** この決定で直結する市民層や担当部局
11. **審議結果・出典:** 可決・否決などの結果と、根拠となる会議へのリンク
12. **過去情報・ステータス更新:** 新着議事録が既存の議案の審議状況や続報に影響するか確認し、根拠と承認を得て必要な項目を更新する。

AIが作成した本文・状態・出典を先にユーザーへ提示する。本番DBへの書き込みと公開は別途承認を得て、議案ID、会期、表示先、更新件数を照合する。

## 5. 会派・議員個人の賛否を追加・更新する手順

### 5.1 更新場所と表示ルール

- 賛否はDBの本文ではなく、[bill-vote-snapshots.ts](../web/src/features/committee-minutes/shared/data/bill-vote-snapshots.ts) の `BILL_VOTE_SNAPSHOTS` に保存する。管理画面で本文や公開状態を変更するだけでは、賛否は追加・更新されない。
- 表示には既存の [BillVoteSection](../web/src/features/committee-minutes/shared/components/bill-vote-section.tsx) を使う。本文末の「審議結果・出典」の後に、賛成・反対の人数、会派・個人、採決不参加者、公式PDFのページリンクを表示する。
- 「党」の名称を独自に付けず、公式資料に記載された**採決当時の会派名**を使用する。会派内の投票者全員の賛否が一致した場合のみ会派名にまとめる。同じ会派で賛否が分かれた場合と無所属は個人名を表示する。この集約は [groupBillVotes](../web/src/features/committee-minutes/shared/utils/bill-votes.ts) が行うため、表示用の会派別人数を別途手入力しない。
- 議長・欠席・退席・法律上の除外は、賛成・反対の人数に含めず別欄に表示する。会派の所属人数と、その採決で投票した人数を混同しない。
- 会派リンクは現在の議員一覧、個人リンクは現在の議員紹介を参照する。採決当時の会派や氏名を現在の所属へ書き換えない。個人の `politicianId` は氏名と照合し、本人を確認できない場合は `null` として誤ったリンクを付けない。

### 5.2 公式資料と対象議案を照合する

1. 大分市議会の該当会期の議決結果賛否一覧表を取得する。PDFのURLが同じでも内容が更新される場合があるため、更新時に資料を再確認する。
2. `bills.id`、会期・年、議案番号、正式な議案名を照合する。同名の条例改正や別会期の同番号を取り違えない。委員会での採決と本会議での採決も区別する。
3. PDFの会派・議員欄の並びと、議案行の**各議員の記号**を一人ずつ照合する。PDFの抽出テキストだけでは改行・列ずれ・斜線が欠落することがあるため、元の表も目視確認する。単に「全員」「多数」「可決」と記されているだけでは、個人の賛否を推定しない。
4. 記号は `○`＝賛成、`×`＝反対、`欠`＝欠席、`退`＝退席、`除`＝法律上の採決除外、`議`＝議長の採決不参加とする。公式PDFの `〇` は確認のうえ `○` に統一する。議長の斜線を空欄・欠席・反対と誤認しない。
5. 予算や条例の所管部分だけを紹介するカードでは、正式な議案全体を `targetTitle` とし、「所管分だけではなく議案全体への賛否」と `scopeNote` に明記する。
6. 反映前に、対象一覧、賛成・反対人数、会派・個人別の内訳、採決不参加者、出典URLとページ、訂正する場合の変更前後をユーザーに提示する。内容と公開の承認を得てから掲載する。確認できない個人票は埋めず、未確認事項として示す。

### 5.3 データを編集する

1. 必ずworktreeで作業する。新規議案はスナップショットを追加し、訂正は同じ `billId` の記録を更新する。同一IDの重複行を作らず、議案本文・公開状態を無関係に変更しない。
2. 各記録に次の項目を設定する。型は [BillVoteSnapshot](../web/src/features/committee-minutes/shared/types/bill-vote.ts) を参照する。

   | 項目 | 設定する内容 |
   |---|---|
   | `billId` | 対象の `bills.id` |
   | `billNumber` | 公式資料の議案番号 |
   | `targetTitle` | 採決対象の正式な議案名 |
   | `meeting` | 年・回次を含む会期 |
   | `sourceUrl` / `sourcePage` | 公式PDFのURL / 1始まりのページ番号 |
   | `scopeNote` | 所管分・一部施策と議案全体の区別など、必要な注意書き |
   | `votes` | 議員ごとの `politicianId`・氏名・採決時点の会派・投票結果 |

3. 既存の会派別名簿と記号列を使う場合は `expandBillVotes(名簿, 記号列)` を使用する。会派の順番・各会派内の議員順・記号数をPDFに合わせる。過去と同じ人数や会派だからという理由で、既存の名簿・投票パターンを流用しない。
4. `ROSTER_2026` や共通の記号列を変更すると、それを使う過去の議案にも影響する。新しい採決で議員構成・所属・議長・個人票が変わった場合は、既存の記録を上書きせず、その採決用の名簿・記号列を追加する。共有値の誤りを訂正する場合は、影響する全議案を再照合する。
5. 議員ごとの結果を直接設定する場合の `result` は、`for` / `against` / `absent` / `withdrawn` / `excluded` / `chair` のいずれかとする。無所属の会派は `null` を使用する。人数だけでなく、誰の票かを必ず記録する。

### 5.4 テスト・公開・掲載後の確認

1. [bill-vote-snapshots.test.ts](../web/src/features/committee-minutes/shared/data/bill-vote-snapshots.test.ts) に、追加・訂正した議案ID、番号、会期、出典ページ、賛否人数と個人の内訳の回帰テストを追加する。既存の議案、議長の扱い、会派内で賛否が分かれる表示も維持する。
2. まず次の対象テストを実行する。

   ```powershell
   pnpm --filter web test --run src/features/committee-minutes/shared/data/bill-vote-snapshots.test.ts src/features/committee-minutes/shared/utils/bill-votes.test.ts src/features/committee-minutes/shared/components/bill-vote-section.test.tsx
   ```

3. push前に `pnpm lint`、`pnpm typecheck`、`pnpm test` を実行する。worktreeでWebの本番ビルドと表示も確認する。既存の環境由来の失敗がある場合は、成功扱いにせず原因と変更箇所の検証結果を分けて報告する。
4. 大分市版の統合ブランチ宛にPRを作成し、公式資料、確認した議案と票数、テスト結果、画面例を記載する。CI・競合・CodeRabbitを確認する。賛否データはコードのため、**DBで議案を公開しただけでは掲載されない**。
5. 承認済みのPRをマージし、現在の大分市版の公開経路に従って**Web側**をデプロイする。Adminだけのデプロイやマージのみで反映済みと判断しない。自動デプロイの設定と実際の公開コミットを確認する。
6. 本番の `/committees/bill-pickups/[id]` を開き、「本会議での賛否」の表示、賛成・反対人数、会派内の分裂票と無所属の個人名、採決不参加者を元資料と照合する。会派・本人のリンク、公式PDFのページリンク、所管範囲の注記を確認し、スマートフォン幅でも表示を確認する。更新対象全件と既存の代表例を確認し、過去の票が変わっていないことも確かめる。
7. 「実装済み」「PR作成済み」「本番掲載済み」を区別して報告する。未デプロイや認証不足の場合は、その状態と残作業を明記する。掲載後に公式資料が訂正された場合は、対象議案と変更前後を再提示し、同じ照合・承認・テスト・Webデプロイ・本番確認を繰り返す。
